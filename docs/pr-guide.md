# PR 가이드

작업 브랜치에서 `pnpm pr`을 실행하면 push 하고 `develop` 대상 PR을 만든다. 이미 열린 PR이 있으면 제목과 본문을 갱신한다.

## 처음 한 번

```bash
brew install gh    # Windows는 winget install GitHub.cli
gh auth login
```

Claude Code가 설치되고 로그인돼 있으면 PR 제목과 "왜?"를 자동으로 채운다. 없어도 `pnpm pr`은 쓸 수 있다.

## 평소 사용

1. 작업 브랜치에서 커밋한다.
2. `pnpm pr`을 실행한다.

본문은 `.pr-body.md`에 만들어진다. 작업 내용은 커밋 제목을 타입별로 묶어 채운다.

## 상황별

| 상황                              | 할 일                                                                                          |
| --------------------------------- | ---------------------------------------------------------------------------------------------- |
| 올리기 전에 본문을 미리 보고 싶다 | `pnpm pr --dry-run`. push 없이 `.pr-body.md`만 만든다                                          |
| 본문을 직접 고치고 싶다           | `.pr-body.md`를 고친 뒤 `pnpm pr`. 같은 브랜치에서는 고친 본문을 그대로 쓴다                   |
| PR을 만든 뒤 커밋을 더 했다       | `pnpm pr`만 하면 push 되고 PR이 갱신된다. 본문까지 새로 만들려면 `rm .pr-body.md` 후 `pnpm pr` |
| `develop`이 아닌 브랜치로 올린다  | `pnpm pr --base <브랜치>`                                                                      |
| 직접 PR을 열고 싶다               | 평소처럼 push 하고 GitHub에서 PR을 만든다. 템플릿이 자동으로 채워진다                          |

## 막힐 때

- **"제목이 없다"로 멈춤:** 커밋이 여러 개이고 Claude 초안을 못 받은 경우다. `.pr-body.md` 첫 줄 `# ` 뒤에 제목(예: `# feat: 그룹 생성 화면 추가`)을 적고 다시 `pnpm pr`.
- **"제목이 커밋 규칙을 어긴다":** 제목도 커밋 메시지와 같은 규칙을 따른다. `타입: 내용` 형식, 명사형 끝맺음, 영문 뒤 조사 붙여 쓰기.
- **"초안 실패: ...":** 뒤에 나오는 원인을 본다. 대부분 Claude Code 미설치나 로그인 문제다. 제목을 직접 적으면 계속 진행된다.
- **"gh를 찾을 수 없다":** 위의 "처음 한 번"을 한다.
